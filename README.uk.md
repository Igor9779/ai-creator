# MUSE — AI Creator Showcase

[English](README.md) · [Русский](README.ru.md) · **Українська**

Преміальний інтерфейс для знайомства з вигаданими ШІ-персонажами, створений передусім для мобільних пристроїв. Кінематографічна фотографія, виразна типографіка та стримана палітра вугільного, слонової кістки й теракотового кольорів супроводжують користувача від вибору персонажа до початку розмови.

## Технології

- React
- TypeScript
- Vite
- Tailwind CSS

Іконки — Lucide React. Шрифти DM Sans та Instrument Serif підключені локально через Fontsource. ESLint перевіряє TypeScript, React hooks і сумісність із Fast Refresh.

## Можливості

- Адаптивний дизайн: однакові картки на мобільних пристроях, збалансована сітка на планшетах та асиметрична композиція на великих екранах.
- Чотири відмінні за зовнішністю й характером ШІ-персонажі: ALEX, RYAN, LUNA та MIA.
- Інтерактивні профілі: панелі, що висуваються знизу, на мобільних пристроях і великі модальні вікна на комп’ютерах.
- Демонстраційна стрічка з оригінальними зображеннями, авторськими нотатками та локальними вподобаннями.
- Інтерактивний демочат: індивідуальні швидкі відповіді, індикатор набору тексту, час повідомлень і підготовлені відповіді на довільний текст.
- Telegram CTA на шляху від знайомства з персонажем до розмови.
- Анімації появи, зображень і взаємодій із підтримкою `prefers-reduced-motion`.
- Клавіатурна навігація, видимі стани фокуса, закриття через Escape і натискання на тло, керування фокусом у модальних вікнах і блокування прокручування сторінки.
- Повна локалізація англійською, українською та російською з доступним із клавіатури перемикачем і збереженням вибраної мови.
- Режим Telegram Mini App у тій самій React-кодовій базі.

## Локальний запуск

Використовуйте Node.js версії 22.13 або новішої в межах гілки 22.x і npm. `.nvmrc` та `package.json` задають узгоджені версії для локальної розробки й деплою.

```sh
npm ci
npm run dev
```

Якщо використовуєте nvm, спочатку виконайте `nvm use`. За вільного порту сервер розробки доступний за адресою `http://127.0.0.1:5173`.

```sh
npm run lint
npm run typecheck
npm run build
npm run preview
```

`lint` відхиляє як помилки, так і попередження. `build` перевіряє TypeScript, а потім створює статичну production-збірку в `dist/`. `preview` запускає цю збірку локально. Для роботи застосунку не потрібні змінні середовища або ключі зовнішніх сервісів.

## Архітектура

```text
src/
  assets/creators/  # Оптимізовані портрети, аватари, зображення стрічки, промпти генерації
  components/      # Секції лендингу, картки, профілі, стрічка, чат, спільні CTA
  data/            # Основні записи персонажів і локальний демоконтент
  hooks/           # Поява секцій і нативна навігація Telegram
  i18n/            # Типізовані словники, провайдер мови, допоміжні функції
  lib/             # Централізована інтеграція з Telegram Web App SDK
  types/           # Моделі персонажів, дописів, розмов і композиції hero
  App.tsx          # Композиція застосунку та вибір режиму відображення
  main.tsx         # Точка входу, підготовка Telegram і локальні шрифти
  index.css        # Тема Tailwind, дизайн-токени та спільні адаптивні стилі
  telegram.css     # Стилі Mini App, безпечні області й адаптація viewport
```

Лендинг складається з `Header`, `Hero`, `CreatorDiscovery`, `Vision`, `FinalConversation` та `Footer`. `CreatorDiscovery` зберігає вибраного персонажа, а `CreatorProfile` керує відкритою сесією профілю. `CreatorPosts` і `CreatorConversation` відповідають за реакції на дописи та стан розмови. Спільні компоненти `TelegramLink` і `ActivityStatus` забезпечують узгоджене відображення CTA та статусу активності.

[`src/data/creators.ts`](src/data/creators.ts) — єдине джерело даних про чотирьох персонажів. Дописи та підготовлені розмови зберігаються в окремих типізованих модулях. Дані для hero та discovery посилаються на основні записи персонажів; вміст не дублюється в компонентах.

[`src/types/creator.ts`](src/types/creator.ts) визначає `Creator`, `Post`, `ChatMessage`, `ChatPrompt` і `MockConversation`. Модель персонажа містить ім’я, категорію, біографію, риси характеру, посилання на локальні зображення, числову статистику, дописи й підказки для розмови. `Post` — дискриміноване об’єднання: допис із зображенням вимагає зображення, альтернативного тексту та розмірів; текстовий допис містить авторську нотатку.

React-стан зберігається в компонентах відповідних функцій. Після повернення з чату зберігаються чернетка, повідомлення, позиція прокручування профілю та локальні реакції. Закриття профілю очищує сесію й скасовує очікувані демовідповіді. Додаткова бібліотека керування станом не використовується.

### Локалізація

За замовчуванням вибрана англійська (`EN`). Перемикач у шапці одразу змінює інтерфейс на українську (`UA`) або російську (`RU`), зберігає налаштування `muse.language` у `localStorage` та оновлює `<html lang>` на `en`, `uk` або `ru`. Якщо сховище браузера недоступне, перемикання працює без збереження налаштування.

[`src/i18n/translations.ts`](src/i18n/translations.ts) містить словники інтерфейсу, зокрема підписи для доступності та метадані документа. TypeScript перевіряє ключі перекладів. `LanguageProvider` надає компонентам `useLanguage()`; окрема i18n-бібліотека та зовнішній сервіс перекладів не використовуються.

Записи персонажів залишаються спільними. Перекладні поля використовують `Localized<T>` і функцію `localized(en, ua, ru)` в наявних модулях даних. Імена, usernames, статистика, посилання на зображення та ідентифікатори контенту не змінюються. Підготовлені повідомлення чату відповідають вибраній мові, а текст відвідувача зберігається в початковому вигляді. Дати дописів форматуються за вибраною локаллю, зберігаючи початкові UTC timestamps.

Щоб змінити текст, оновіть словник інтерфейсу або відповідне локалізоване поле персонажа, допису чи розмови. Для додавання мови потрібно оновити об’єднання `Language`, список мов, словники та локалізовані дані; TypeScript вкаже відсутні записи.

## Telegram Mini App

MUSE підтримує два режими в одній React-кодовій базі: повний самостійний сайт і компактний інтерфейс вибору персонажів усередині Telegram. Інтеграція в [`src/lib/telegram.ts`](src/lib/telegram.ts) завантажує [офіційний Telegram Web App SDK](https://core.telegram.org/bots/webapps) лише під час запуску в середовищі Telegram. Звичайним відвідувачам браузера не потрібні Telegram API або запити SDK.

Mini App викликає `ready()` та `expand()`, зберігає темну палітру MUSE, враховує події зміни viewport і безпечних областей та утримує поле введення у видимій області під час відкриття клавіатури. Нативна кнопка «Назад» повертає з чату до профілю, а потім до списку персонажів. Якщо клієнт підтримує haptics, м’який відгук супроводжує відкриття профілю, початок розмови та вибір швидкої відповіді. Локалізація EN/UA/RU, персонажі, стрічка й демочат спільні для обох режимів.

Для запуску з Telegram вкажіть HTTPS-адресу опублікованого застосунку як Mini App URL у BotFather. Необов’язкове привітання на ім’я використовує неперевірені frontend-дані лише для відображення. Telegram-автентифікація, серверна перевірка `initData`, інфраструктура бота та справжні ШІ-відповіді навмисно залишаються поза межами демоверсії. Telegram CTA на сайті використовують централізовану константу `TELEGRAM_URL` налаштованого Mini App.

Перевірка Mini App охоплює всіх чотирьох персонажів на EN/UA/RU за ширини 375, 390 і 430 px, desktop, зміну висоти під час відкриття клавіатури, старі версії API та React StrictMode. Використовується офіційний SDK з емуляцією нативних подій WebView і Telegram Web iframe. Перевірка в реальному клієнті потребує налаштування BotFather.

## Продуктивність і доступність

Портрети — WebP розміром 800 × 1200, аватари — кадровані зображення облич 256 × 256, фотографії стрічки — WebP 960 × 640. Головний портрет hero завантажується попередньо. Зображення discovery, стрічки та фінальної секції нижче першого екрана використовують нативне відкладене завантаження й явні розміри. Ті самі файли використовуються на лендингу, у профілі та чаті. Усі шрифти й зображення підключені локально.

Чат монтується під час першого відкриття. Спільний IntersectionObserver одноразово запускає появу секцій; за клавіатурного фокуса вміст одразу стає видимим. Нативні діалоги забезпечують семантику модального вікна, стабільне доступне ім’я, обмеження переміщення фокуса всередині вікна, відновлення фокуса та анімації з урахуванням reduced motion. Розміри інтерактивних елементів зручні для дотику.

Походження ШІ-зображень і промпти генерації описані в [`src/assets/creators/README.md`](src/assets/creators/README.md) та [`feed-photography.md`](src/assets/creators/feed-photography.md).

Браузерна перевірка проводилася в Chrome на ширинах 375, 390, 414, 430, 768, 1024, 1280 та 1440 px. Перевірені всі профілі, дописи, відповіді чату, стан сесії, Telegram CTA, клавіатурна навігація, Escape і reduced motion. Автоматичні перевірки доступності й контрасту пройдені, як і перевірки React StrictMode на попередження та скасування очікуваних відповідей. Lint, TypeScript, чисте встановлення за lockfile і production-збірка перевірені окремо.

Перевірка локалізації охопила три мови на ширинах 375, 390, 430, 768, 1024 і 1440 px: 18 адаптивних сценаріїв і 72 шляхи через профілі персонажів. Перевірені збереження мови, мова документа, переклади дописів і підготовлених повідомлень, вибір із клавіатури, мобільна навігація, reduced motion, некоректні налаштування та недоступність сховища. Горизонтального переповнення, непрацюючих зображень і попереджень консолі не виявлено. Перевірки доступності охоплюють відкрите меню мов.

## Деплой

Налаштування Vercel містяться у [`vercel.json`](vercel.json):

| Параметр | Значення |
| --- | --- |
| Фреймворк | Vite |
| Node.js | 22.x |
| Команда встановлення | `npm ci` |
| Команда збірки | `npm run lint && npm run build` |
| Каталог збірки | `dist` |

Імпортуйте репозиторій у Vercel або виконайте `vercel --prod`, попередньо авторизувавшись у Vercel CLI. Змінні середовища, база даних і backend не потрібні. Vite обробляє статичні ресурси, а SPA fallback повертає `index.html` під час прямого відкриття адрес застосунку. Інтерфейс використовує якорі секцій і діалоги замість окремих маршрутів профілів. Докладніше — у [посібнику з деплою Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite).

`node_modules/`, `dist/`, `.vercel/`, файли середовища, логи та метадані macOS виключені з Git. До деплою не потрапляють локальні залежності й артефакти збірки; Vercel створює production-збірку з вихідного коду та lockfile.

## Примітки

Персонажі, дописи, соціальна статистика, індикатори активності та розмови — вигадані демонстраційні дані. Кожен персонаж має п’ять недавніх дописів і п’ять підготовлених відповідей чату. Імітація набору тексту триває 1,1 секунди; на довільні повідомлення надається локальна резервна відповідь. Справжня ШІ-модель не викликається; повідомлення й реакції не надсилаються до зовнішнього сервісу.

Усі Telegram CTA на сайті відкривають налаштований Mini App бота `@muse_ai_creators_bot`. Адреса задається лише константою `TELEGRAM_URL` у [`src/data/site.ts`](src/data/site.ts). У режимі Mini App ці CTA приховані. Перехід до Telegram не переносить локальну розмову.

Це frontend-вітрина без backend, бази даних, автентифікації, платежів або зовнішніх ШІ API.
