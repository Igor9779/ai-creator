# MUSE — AI Creator Showcase

[English](README.md) · **Русский** · [Українська](README.uk.md)

Премиальный интерфейс для знакомства с вымышленными ИИ-персонажами, созданный прежде всего для мобильных устройств. Кинематографичная фотография, выразительная типографика и сдержанная палитра угольного, слоновой кости и терракотового цветов сопровождают пользователя от выбора персонажа до начала разговора.

## Технологии

- React
- TypeScript
- Vite
- Tailwind CSS

Иконки — Lucide React. Шрифты DM Sans и Instrument Serif подключены локально через Fontsource. ESLint проверяет TypeScript, React hooks и совместимость с Fast Refresh.

## Возможности

- Адаптивный дизайн: одинаковые карточки на мобильных устройствах, сбалансированная сетка на планшетах и асимметричная композиция на больших экранах.
- Четыре визуально и по характеру разных ИИ-персонажа: ALEX, RYAN, LUNA и MIA.
- Интерактивные профили: выдвигающиеся снизу панели на мобильных устройствах и крупные модальные окна на компьютерах.
- Демонстрационная лента с оригинальными изображениями, авторскими заметками и локальными лайками.
- Интерактивный демочат: индивидуальные быстрые ответы, индикатор набора текста, время сообщений и подготовленные ответы на произвольный текст.
- Telegram CTA на пути от знакомства с персонажем до разговора.
- Анимации появления, изображений и взаимодействий с поддержкой `prefers-reduced-motion`.
- Клавиатурная навигация, видимые состояния фокуса, закрытие по Escape и нажатию на фон, управление фокусом в модальных окнах и блокировка прокрутки страницы.
- Полная локализация на английский, украинский и русский с доступным с клавиатуры переключателем и сохранением выбранного языка.
- Режим Telegram Mini App в той же React-кодовой базе.

## Локальный запуск

Используйте Node.js версии 22.13 или новее в пределах ветки 22.x и npm. `.nvmrc` и `package.json` задают согласованные версии для локальной разработки и деплоя.

```sh
npm ci
npm run dev
```

Если используете nvm, сначала выполните `nvm use`. При свободном порте сервер разработки доступен по адресу `http://127.0.0.1:5173`.

```sh
npm run lint
npm run typecheck
npm run build
npm run preview
```

`lint` отклоняет как ошибки, так и предупреждения. `build` проверяет TypeScript, затем создаёт статическую production-сборку в `dist/`. `preview` запускает эту сборку локально. Для работы приложения не нужны переменные окружения или ключи внешних сервисов.

## Архитектура

```text
src/
  assets/creators/  # Оптимизированные портреты, аватары, изображения ленты, промпты генерации
  components/      # Секции лендинга, карточки, профили, лента, чат, общие CTA
  data/            # Основные записи персонажей и локальный демоконтент
  hooks/           # Появление секций и нативная навигация Telegram
  i18n/            # Типизированные словари, провайдер языка, вспомогательные функции
  lib/             # Централизованная интеграция с Telegram Web App SDK
  types/           # Модели персонажей, постов, разговоров и композиции hero
  App.tsx          # Композиция приложения и выбор режима отображения
  main.tsx         # Точка входа, подготовка Telegram и локальные шрифты
  index.css        # Тема Tailwind, дизайн-токены и общие адаптивные стили
  telegram.css     # Стили Mini App, безопасные области и адаптация viewport
```

Лендинг состоит из `Header`, `Hero`, `CreatorDiscovery`, `Vision`, `FinalConversation` и `Footer`. `CreatorDiscovery` хранит выбранного персонажа, а `CreatorProfile` управляет открытой сессией профиля. `CreatorPosts` и `CreatorConversation` отвечают за реакции на посты и состояние разговора. Общие компоненты `TelegramLink` и `ActivityStatus` обеспечивают единое отображение CTA и статуса активности.

[`src/data/creators.ts`](src/data/creators.ts) — единый источник данных о четырёх персонажах. Посты и подготовленные разговоры находятся в отдельных типизированных модулях. Данные для hero и discovery ссылаются на основные записи персонажей; содержимое не дублируется в компонентах.

[`src/types/creator.ts`](src/types/creator.ts) определяет `Creator`, `Post`, `ChatMessage`, `ChatPrompt` и `MockConversation`. Модель персонажа включает имя, категорию, биографию, черты характера, ссылки на локальные изображения, числовую статистику, посты и подсказки для разговора. `Post` — дискриминируемое объединение: пост с изображением требует изображения, альтернативного текста и размеров; текстовый пост содержит авторскую заметку.

React-состояние хранится в компонентах соответствующих функций. При возврате из чата сохраняются черновик, сообщения, положение прокрутки профиля и локальные реакции. Закрытие профиля очищает сессию и отменяет ожидающие демоответы. Дополнительная библиотека управления состоянием не используется.

### Локализация

По умолчанию выбран английский (`EN`). Переключатель в шапке сразу меняет интерфейс на украинский (`UA`) или русский (`RU`), сохраняет настройку `muse.language` в `localStorage` и обновляет `<html lang>` на `en`, `uk` или `ru`. Если хранилище браузера недоступно, переключение работает без сохранения настройки.

[`src/i18n/translations.ts`](src/i18n/translations.ts) содержит словари интерфейса, включая подписи для доступности и метаданные документа. TypeScript проверяет ключи переводов. `LanguageProvider` предоставляет компонентам `useLanguage()`; отдельная i18n-библиотека и внешний сервис переводов не используются.

Записи персонажей остаются общими. Переводимые поля используют `Localized<T>` и функцию `localized(en, ua, ru)` в существующих модулях данных. Имена, usernames, статистика, ссылки на изображения и идентификаторы контента не меняются. Подготовленные сообщения чата следуют выбранному языку, а текст посетителя сохраняется в исходном виде. Даты постов форматируются согласно выбранной локали, сохраняя исходные UTC timestamps.

Чтобы изменить текст, обновите словарь интерфейса или соответствующее локализованное поле персонажа, поста либо разговора. Для добавления языка нужно обновить объединение `Language`, список языков, словари и локализованные данные; TypeScript укажет недостающие записи.

## Telegram Mini App

MUSE поддерживает два режима в одной React-кодовой базе: полный самостоятельный сайт и компактный интерфейс выбора персонажей внутри Telegram. Интеграция в [`src/lib/telegram.ts`](src/lib/telegram.ts) загружает [официальный Telegram Web App SDK](https://core.telegram.org/bots/webapps) только при запуске в окружении Telegram. Обычным посетителям браузера не нужны Telegram API или запросы SDK.

Mini App вызывает `ready()` и `expand()`, сохраняет тёмную палитру MUSE, учитывает события изменения viewport и безопасных областей и удерживает поле ввода в видимой области при открытии клавиатуры. Нативная кнопка «Назад» возвращает из чата в профиль, затем к списку персонажей. Если клиент поддерживает haptics, мягкий отклик сопровождает открытие профиля, начало разговора и выбор быстрого ответа. Локализация EN/UA/RU, персонажи, лента и демочат используются совместно в обоих режимах.

Для запуска из Telegram укажите HTTPS-адрес опубликованного приложения как Mini App URL в BotFather. Необязательное приветствие по имени использует непроверенные frontend-данные только для отображения. Telegram-аутентификация, серверная проверка `initData`, инфраструктура бота и настоящие ИИ-ответы намеренно не входят в рамки демо. Telegram CTA на сайте используют централизованную константу `TELEGRAM_URL` настроенного Mini App.

Проверка Mini App охватывает всех четырёх персонажей на EN/UA/RU при ширине 375, 390 и 430 px, desktop, изменение высоты при открытии клавиатуры, старые версии API и React StrictMode. Используется официальный SDK с эмуляцией нативных событий WebView и Telegram Web iframe. Проверка в реальном клиенте требует настройки BotFather.

## Производительность и доступность

Портреты — WebP размером 800 × 1200, аватары — кадрированные изображения лиц 256 × 256, фотографии ленты — WebP 960 × 640. Главный портрет hero загружается предварительно. Изображения discovery, ленты и финальной секции ниже первого экрана используют нативную ленивую загрузку и явные размеры. Одни и те же файлы используются на лендинге, в профиле и чате. Все шрифты и изображения подключены локально.

Чат монтируется при первом открытии. Общий IntersectionObserver однократно запускает появление секций; при клавиатурном фокусе содержимое сразу становится видимым. Нативные диалоги обеспечивают семантику модального окна, стабильное доступное имя, ограничение перемещения фокуса внутри окна, восстановление фокуса и анимации с учётом reduced motion. Размеры интерактивных элементов удобны для касания.

Происхождение ИИ-изображений и промпты генерации описаны в [`src/assets/creators/README.md`](src/assets/creators/README.md) и [`feed-photography.md`](src/assets/creators/feed-photography.md).

Браузерная проверка проводилась в Chrome на ширинах 375, 390, 414, 430, 768, 1024, 1280 и 1440 px. Проверены все профили, посты, ответы чата, состояние сессии, Telegram CTA, клавиатурная навигация, Escape и reduced motion. Автоматические проверки доступности и контраста пройдены, как и проверки React StrictMode на предупреждения и отмену ожидающих ответов. Lint, TypeScript, чистая установка по lockfile и production-сборка проверены отдельно.

Проверка локализации охватила три языка на ширинах 375, 390, 430, 768, 1024 и 1440 px: 18 адаптивных сценариев и 72 пути через профили персонажей. Проверены сохранение языка, язык документа, переводы постов и подготовленных сообщений, выбор с клавиатуры, мобильная навигация, reduced motion, некорректные настройки и недоступность хранилища. Горизонтального переполнения, неработающих изображений и предупреждений консоли не обнаружено. Проверки доступности включают открытое меню языков.

## Деплой

Настройки Vercel находятся в [`vercel.json`](vercel.json):

| Параметр | Значение |
| --- | --- |
| Фреймворк | Vite |
| Node.js | 22.x |
| Команда установки | `npm ci` |
| Команда сборки | `npm run lint && npm run build` |
| Каталог сборки | `dist` |

Импортируйте репозиторий в Vercel или выполните `vercel --prod`, предварительно авторизовавшись в Vercel CLI. Переменные окружения, база данных и backend не требуются. Vite обрабатывает статические ресурсы, а SPA fallback возвращает `index.html` при прямом открытии адресов приложения. Интерфейс использует якоря секций и диалоги вместо отдельных маршрутов профилей. Подробнее — в [руководстве по деплою Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite).

`node_modules/`, `dist/`, `.vercel/`, файлы окружения, логи и метаданные macOS исключены из Git. В деплой не попадают локальные зависимости и артефакты сборки; Vercel создаёт production-сборку из исходного кода и lockfile.

## Примечания

Персонажи, посты, социальная статистика, индикаторы активности и разговоры — вымышленные демонстрационные данные. У каждого персонажа пять недавних постов и пять подготовленных ответов чата. Имитация набора текста длится 1,1 секунды; на произвольные сообщения выдаётся локальный запасной ответ. Настоящая ИИ-модель не вызывается; сообщения и реакции не отправляются во внешний сервис.

Все Telegram CTA на сайте открывают настроенный Mini App бота `@muse_ai_creators_bot`. Адрес задаётся только константой `TELEGRAM_URL` в [`src/data/site.ts`](src/data/site.ts). В режиме Mini App эти CTA скрыты. Переход в Telegram не переносит локальный разговор.

Это frontend-витрина без backend, базы данных, аутентификации, платежей или внешних ИИ API.
